# CAAC理论题库 · caac-quiz

> 站点名：**CAAC理论题库**（在线地址见下方「在线地址 / 部署」一节）

一个纯前端（零依赖、无构建）的 CAAC 超视距（机长）理论题库刷题应用，单 HTML + 原生 JS + CSS，支持背题 / 章节 / 随机 / 错题重做 / 模拟考试 / 统计 / 收藏存疑 / 深浅主题 / 响应式。题库只有一个（真题库 1691 题），不做切换。

## 数据规范化

源题库在早期被一次「清洗」脚本误伤：**把选项里的独立大写字母（A/B/C/D）当成选项标签删掉或拆开**，造成题干截断、选项丢失字母、选项粘连、答案指向空项等问题。此外还混入大量 OCR 残迹（繁体字、乱码字符、罗马数字被识别成数字 1 或小写 l、公式变量丢失）。已通过 `tools/build_bank.py` 统一修复：

```bash
python tools/build_bank.py               # 只重新生成 bank-real.js
python tools/build_bank.py --write-src   # 同时把清理结果回写 data/questions.js
python tools/scan_quality.py data/questions.js   # 体检（应为 0 处问题）
python tools/scan_text.py                        # 文本层体检
```

- **机械清理**（全库）：去空选项、去选项尾部「正确答案/参考答案」标签、去首尾空白、剥离解析开头的「解析：」「：」等标签残留。
- **全库文本修正**（`TEXT_FIX` / `TEXT_RE`，均为无歧义替换）：繁体字（減→减、決→决）、相邻重复字（飞飞机→飞机、飞飞行→飞行）、罗马数字 OCR 伪影（`|、|I 类`→`Ⅰ、Ⅱ类`、`X1 类`→`XI 类`、`l 类`→`Ⅰ类`）、缩写缺字母（VF→VFR）、西里尔/日文字符（Р→P、カ→力）、公式变量（`L=1/2pCSV2`→`L=1/2ρCSV²`、`PRp`→`PRρ`）、中文里粘连的英文串（`ElectronicSpeedController`→`Electronic Speed Controller`）、中文顿号/逗号两侧空格等。
- **结构重建/文字修复**（逐题对照其自带解析重建，见 `build_bank.py` 的 `MANUAL` 表与 `EXP_FIX`）：
  152、178（选项丢失类别字母）、229（选项粘连）、559、644、1514（题干尾巴混入首选项）、
  710（选项被拆两半）、1039（答案原指向空项）、1092（选项被拆 5 段）、
  1486、1525（题干被截断）、48（错别字）、397（缺空括号）、73（解析 OCR）。
- **内容矛盾修正**（3 道，查《轻小无人机运行规定（试行）》原文定论）：16、21、217。
- **解析截断标记**（约 1000 道）：源题库把解析截断在 100 字，自动补 `……`。

- 换了题库或改了 `assets/` 记得同时改 `index.html` 里的 `?v=` 版本号，否则浏览器会吃缓存

### 本机网络注意事项（重要）

这台机器直连 `github.com:443` 不通，且 shell 环境里被注入了 `GIT_TERMINAL_PROMPT=0`（会让
Git Credential Manager 拒绝弹认证界面）。push 请用：

```bash
env -u http_proxy -u https_proxy \
    git -c http.proxy=http://127.0.0.1:7897 -c https.proxy=http://127.0.0.1:7897 \
        -c http.version=HTTP/1.1 push origin main
```

- 先用 `env -u` 把环境里那两个可能指向死端口的 `http_proxy` / `https_proxy` 摘掉，再显式指定 7897
- 代理端口 `7897` 是你本机的可用代理；环境变量里的 `http_proxy` 端口会变、可能是死的
- `-c http.version=HTTP/1.1` 能绕开部分代理对分块响应的处理问题
- 该通道偶发超时，**重试一两次即可成功**
- `api.github.com` 直连是通的，所以查仓库/Pages/Actions 状态不用代理

## 替换真实题库

题库字段契约（`app.js` 头部注释）：

```js
{
  name, version, source, cats:[章节名,...],
  questions:[
    { id, cat, type:'single'|'multi', q, opts:[选项,..],
      ans:number | number[],   // 单选=正确下标，多选=下标数组
      exp:'',                  // 答案解析
      flag:''                  // 存疑原因（空字符串=正常，否则会标 ⚠）
    }
  ]
}
```

把新题库按以上结构写成 `window.CAAC_BANK = {...}` 覆盖 `data/bank-real.js` 即可 —— `assets/app.js` 直接读 `window.CAAC_BANK` 这个全局变量，没有题库映射表。改完记得同步 `index.html` 里的 `?v=`。

## ✅ 原「解析被截断到 100 字」硬伤：已用辅助题库补全

`questions.original.js` 原件把**所有解析统一截断到 100 字**（1691 题中约 1000 道断在句子中间），全文不在文件里。后来拿到一份**同源但解析未截断**的辅助题库 `data/reference-bank.json`（1621 题，`CAAC机长【分章练习】题库-汇总 PDF` 的转录版），已借此补全。

**交叉校验结果**（`python tools/cross_check.py`，报告见 `tools/cross_report.txt`）：

| 维度 | 结果 |
|------|------|
| 编号对齐 | 辅助库 1–1621 与本方一一对应，题干相似度均值 **0.996** |
| **答案冲突** | **0 处**（1619 道共有题逐题比对，同题干同选项却答案不同 = 无） |
| 选项集差异 | 55 题同条数文本不同 + 12 题条数不同 —— **全部是辅助库仍为未修的原始形态，本方是修好的那一版** |
| 题干差异 | 12 题，均为本方已重建的损坏题 + 罗马数字修正题 |

**编号错位**（逐题核对，非猜测）：本方 `#45 ↔ q0044-2`、`#46 ↔ q0045`、`#1436 ↔ q1343-2`；辅助库缺 46、1436 两个号，本方多出 1622–1691 共 70 题。

**补全做法**（`build_bank.py` 的 `RECOVER` 段）：

1. 按上表把本方题号映射到辅助库题号；
2. 对辅助库文本套用**与本题相同的** `text_fix` + `EXP_FIX` 再比对（消除两边规范化程度不同带来的假差异）；
3. 仅当**公共前缀 ≥ 原文 75%** 时才采用辅助库文本 —— 即"我方文本是辅助库文本的前缀"，属于安全续写，不会张冠李戴；
4. 长度相当的（辅助库只比我方长 0–5 字）说明**原文本来就完整、只是不以句号结尾**，采用辅助库版本并**去掉误标的 `……`**。

结果：**1023 条解析采用辅助库完整文本**，解析平均长度 100 → **115** 字；仍带 `……` 的从 1000 条降到 **1 条**（`#964`，辅助库自身也在该处截断）。补全过程**不动选项、不动答案**，只改解析（唯一改题的 `#1436` 是题干重建）。

关闭补全：`python tools/build_bank.py --no-recover`。整个流程幂等（连跑两次 `--write-src` 产物字节一致）。

## Logo 与站点名

`assets/` 下三张图全部由 `tools/make_logo.py` 从一张带白底的截图 `logo-src.png` 生成，不要手改产物：

```bash
python tools/make_logo.py logo-src.png     # 省略参数时默认读根目录的 logo-src.png
```

| 产物 | 来源 | 用途 |
| --- | --- | --- |
| `assets/logo.png` | 整枚 logo，白边裁掉 | 备用（想用整枚时把 `index.html` 的 img src 换成它） |
| `assets/logo-mark.png` | 只取彩色徽标区域 | 标题栏（`index.html` 的 `.logo img`） |
| `assets/favicon.png` | 徽标居中进 64×64 透明方图 | `rel="icon"` / `apple-touch-icon` |

两个容易踩的坑，都写在脚本注释里了：

- **必须抠白底**。站点有深色主题，白底图在深色顶栏上会变成一个白方块。脚本按 `min(r,g,b)` 估 alpha 再反预乘还原颜色，抗锯齿边缘不糊。
- **徽标要按「颜色」切，不能按「位置」切**。想只留徽标时，第一版按行切（`content_bands()`）会连「中国民航」黑字一起带进来；改成饱和度筛选后，黑字的 ClearType subpixel 彩色描边又被误判成「有颜色」，
  外接框直接撑到整图高度。最终判据是 `max-min > 60` **且** `max > 90` —— 描边像素偏暗，被亮度这道闸门滤掉。
  `content_bands()` 已保留在脚本里但不再调用。

深色主题下蓝色飞翼对比度偏低，`styles.css` 里用 `[data-theme="dark"] .logo img { filter: brightness(1.25) drop-shadow(...) }` 提亮。

回归校验：`node tools/shot_logo.js` —— 用 playwright 跑桌面/移动 × 浅色/深色四种组合，断言 logo 的 `naturalWidth > 0`（真的加载成功，不是裂图）、`document.title` 与顶栏站名，并各截一张 `.topbar` 图到 `tools/logo-*.png` 供肉眼确认。
